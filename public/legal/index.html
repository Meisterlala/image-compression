Implementation & licenses

Image compression demo is a static, client-side compression demonstration. Your image is read locally; no upload endpoint, external analytics, remote inference, or third-party fonts are used. Encoding, output decoding and quality metrics run in WebAssembly on your CPU. The browser imports images and prepares 8-bit sRGB pixels using its canvas APIs.

JPEG AI is experimental

JPEG AI is the learned image compression standard ISO/IEC 6048-1. This application uses zenjpegai, pinned to commit 1192fca6b6c2fdc4dcf29a6c8064c53a987caf59. This is not a certification of conformance. The .jai extension is a project convention, not a claim of a registered media type or native browser support.

All four trained models for each of Simple, Base and High Operation Point are available in the JPEG AI tab. The table headers form a three-way full-name operating-point selector; the heading text triggers trade-off/use-case tooltips without info icons. A compact matrix shows four model rows and all three operating-point columns on desktop and mobile. Repeated per-model file sizes appear in the column headings: about 25 MiB for SOP, 26 MiB for BOP or 54 MiB for HOP. Individual sizes are shown if they differ. Selection is labelled explicitly, without status dots. A selected cell has a persistent border and checkmark; automatic selection highlights the whole column, and a summary states the active choice. Centered Download/Remove actions have distinct neutral arrow/red trash buttons. Weights are separate from the compressed image. Clicking a cell selects that specific model and point; clicking a column heading chooses automatic model selection within that family. Downloading or removing weights does not change selection. A stored-model-size total is shown below the matrix; there is no automatic cleanup or expiry. Only the Download button fetches weights, verified with SHA-256 into separate browser cache entries. Encoding is cache-only and requires the selected model, or all four models for automatic target-bitrate search (about 99 MiB, 104 MiB or 218 MiB). Table actions support removal and cancellation; no model file export/import is provided. Browser Cache Storage is required for JPEG AI, and may be evicted or denied; workers never silently download missing models.

SOP, BOP and HOP are supported with advanced optional coding tools off. SOP uses the lightest decoder, useful for fast previews or constrained devices with potentially lower fidelity; BOP is the balanced general-purpose default. HOP aims for better compression with slower decoding and higher memory use; it is not guaranteed to produce smaller output for every image or setting. All three points support fixed-model quantisation and target-bpp search. SOP reuses BOP analysis weights but has its own lightweight synthesis weights. HOP preflight includes a conservative synthesis-memory bound and retained model storage, not just the encoder estimate. It does not provide HDR, animation, alpha preservation, arbitrary model files, WebGPU or a server fallback.

Cool-chic 5.0 reduced profile

The Cool-chic tab uses a self-contained CPU-only Rust encoder and decoder adapted from Cool-chic v5.0.0. This is an experimental reduced profile, not the full reference encoder: three latent grids, linear synthesis and a linear spatial entropy model, without IFCE or the reference training/presets. Fine colour detail and compression performance differ substantially; quality 100 is not lossless. Its per-image model is trained during encoding and included in the .cool file, counted in file size. There are no pretrained weights or model downloads. Output is tested against the reference Python decoder; the Rust decoder supports only this profile. Inputs are limited to 4 million pixels and dimensions below 16384. Decoding includes canonical entropy validation. See the source crate README for exact restrictions and tests, the Orange BSD-3-Clause notice, and licenses for constriction and probability.

What the numbers mean

Encoded size includes the output file/container, not the separate model or WASM downloads. File-size change appears when hovering or focusing the encoded file size, calculated as a percentage: (1 − encoded file bytes / reference file bytes) × 100. Full-resolution references use the uploaded file's byte count; resized references use an actual browser-generated PNG. Negative savings are shown as a percentage larger. Each result retains its encode-time reference size, so changing the selected downscale does not alter an existing result's percentage. PSNR and MSE use RGB channels; SSIM uses non-overlapping 8×8 Rec.709 luma windows with population variance, K1=.01, K2=.03 and L=255. This is not MS-SSIM. Identical pixels have infinite PSNR. None of these metrics is a guarantee of perceptual fidelity.

Startup, encoding, decoding and metric times are measured separately for each codec. Encode time and decode time are separate columns in the shared comparison table. Unencoded formats have empty cells; the input is the quality reference and its historical codec times are unknown. The reference is labelled Original at full resolution or Downscaled after resizing. Its bits/pixel are calculated from actual reference bytes and dimensions. Codec rows retain their latest output and encode-time reference metadata across downscale changes; only a new source selection clears them. The separate image comparison can display the current input or either of two encoded outputs; its selections do not change the table's encode-time quality measurements. Dimensions are shown per row, since results can use different sizes. Best and worst encoded values in each column are green and red, excluding the original. Quality and bitrate ties use the displayed precision. Jobs run one at a time to avoid CPU contention, and settings/results are independent. Every job starts a fresh worker; cache reads and WASM initialization are startup work. Explicit model downloads happen separately, before encoding. The memory number is an upstream estimate of the encode working set, not a measured peak of the whole browser.

Source images are composited on white. Full resolution is the default and preserves source dimensions. Downscaling to 2048, 1024, 512 or 256 is optional, preserves aspect ratio, and never upscales. Files are capped at 40 MiB and source/working images at 40 megapixels after browser decoding. JPEG AI has a 3 GiB estimated working-memory cap. Jobs above 1.5 GiB require explicit confirmation before model loading and encoding; waiting for confirmation is excluded from timings. These estimates do not guarantee the browser has enough memory. No fallback silently changes image dimensions. Malformed source decoders may allocate memory before the dimension check; this app is not a sandbox for hostile images.
