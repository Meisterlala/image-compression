Implementation & licenses

Image compression demo is a static, client-side compression demonstration. Your image is read locally; no upload endpoint, external analytics, remote inference, or third-party fonts are used. Encoding, output decoding and quality metrics run in WebAssembly on your CPU. The browser imports images and prepares 8-bit sRGB pixels using its canvas APIs.

JPEG AI is experimental

JPEG AI is the learned image compression standard ISO/IEC 6048-1. This application uses zenjpegai, pinned to commit 1192fca6b6c2fdc4dcf29a6c8064c53a987caf59. This is not a certification of conformance. The .jai extension is a project convention, not a claim of a registered media type or native browser support.

All four trained BOP models are available inline under the JPEG AI pane’s settings. Weights are separate from the compressed image. One encoder/decoder bundle is about 26 MiB; target-bitrate search needs about 104 MiB. Downloads are verified with SHA-256 before use and may be cached in your browser. You can explicitly download, remove, export and re-import verified weights through the library. Browser storage may be evicted.

The initial version uses only the BOP profile with advanced coding tools off. It supports fixed-model quantisation and target-bpp search. It does not provide HDR, animation, alpha preservation, arbitrary model files, WebGPU or a server fallback.

What the numbers mean

Encoded size includes the output file/container, not the separate model or WASM downloads. The primary compression ratio is raw working RGB bytes (width × height × 3) divided by encoded file bytes. Upload-to-encoded ratio is shown separately in the file details because the uploaded image may have different dimensions. PSNR and MSE use RGB channels; SSIM uses non-overlapping 8×8 Rec.709 luma windows with population variance, K1=.01, K2=.03 and L=255. This is not MS-SSIM. Identical pixels have infinite PSNR. None of these metrics is a guarantee of perceptual fidelity.

Startup, encoding, decoding and metric times are measured separately for each codec. Encode time and decode time are equally prominent in each of the four panes. Jobs run one at a time to avoid CPU contention, and settings/results are independent. Every job starts a fresh worker; model downloads/cache reads and WASM initialization are startup work. The memory number is an upstream estimate of the encode working set, not a measured peak of the whole browser.

For transparency, source images are composited on white; large images are resized before encoding. Resizing affects the result. Files are capped at 40 MiB, imported images at 40 megapixels after browser decoding, and working images at a 1024-pixel maximum edge. Malformed source decoders may allocate memory before the dimension check; this app is not a sandbox for hostile images.
